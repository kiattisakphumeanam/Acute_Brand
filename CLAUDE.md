
# ACUTE — Project Instructions

## 1. Project Context

This is the existing ACUTE fashion brand website built with Next.js.

The website is already implemented and has been reviewed.
The current task is FRONTEND REFINEMENT, not rebuilding the website.

Your responsibility is to improve the existing interface while preserving
the current architecture, features, and brand identity.

## 2. Brand Identity

Brand: ACUTE

Brand Essence:
"Intentional in-between"

Brand Philosophy:
"Brilliance meets kindness."

Brand Personality:
- Confidence
- Intelligence
- Self-expression
- Individuality
- Softness
- Empathy
- Warmth
- Acceptance

Brand Tone:
- Simplicity and purpose
- Empathy and openness
- Quiet assurance

### Color Palette

- ACUTE Red: #AE3C31
- Blue: #DCE7F2
- White: #F7F3EE
- Black: #2F3135
- Grey: #B7AFA6

### Typography

- Primary: Minion Variable Concept
- Secondary: Josefin Sans

Respect the existing font configuration and assets.
Do not replace fonts without a clear reason.

## 3. Main Objective

Improve the existing website in these areas:

- Layout and composition
- Spacing and alignment
- Typography and visual hierarchy
- Responsive behavior
- Component consistency
- User experience
- Interaction details
- Visual polish

Remove generic AI-generated design patterns.

## 4. Anti AI-Slop Rules

Avoid introducing:

- Unnecessary gradients
- Excessive rounded cards
- Generic card-based layouts
- Random decorative elements
- Unnecessary shadows
- Excessive animations
- Floating elements without purpose
- Generic hero sections
- Repetitive section compositions
- Arbitrary icons
- Unnecessary visual effects

Every visual element must have a clear purpose.

Do not make the entire website minimal just for the sake of minimalism.
Design decisions must support ACUTE's brand identity.

## 5. Development Rules

- Inspect existing code before modifying it.
- Reuse existing components whenever possible.
- Preserve existing functionality.
- Preserve current routes and navigation.
- Preserve API integration and backend logic.
- Do not rewrite entire pages unnecessarily.
- Do not introduce unnecessary dependencies.
- Follow the existing project structure.
- Keep components reusable and maintainable.
- Use semantic HTML.
- Follow responsive design principles.
- Maintain accessibility and keyboard usability.

## 6. Workflow

For each page:

1. Inspect the current implementation.
2. Understand the page's purpose and user journey.
3. Identify layout and visual problems.
4. Identify generic AI-generated patterns.
5. Explain the proposed improvements.
6. Wait for approval before making significant changes.
7. Implement changes incrementally.
8. Check desktop and mobile layouts.
9. Verify existing interactions and functionality.
10. Report modified files and remaining issues.

## 7. Important Constraints

DO NOT:

- Rebuild the entire website.
- Redesign every page without approval.
- Change the brand identity.
- Change backend behavior.
- Remove existing features.
- Replace real product images with placeholders.
- Hardcode product data into components.
- Modify unrelated files.
- Assume a design change is better without evaluating its purpose.

## 8. Quality Standard

The final result should feel:

- Intentional
- Editorial
- Refined
- Warm
- Authentic
- Consistent
- Production-ready

Prioritize design quality, usability, maintainability, and consistency.

Make fewer but more meaningful improvements.
